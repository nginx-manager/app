# v1.2.4 — 사이트 지우기, 사이트별 변경 이력, 원문 사이트 로그

- 날짜: 2026-10-30
- 이미지: `ghcr.io/nginx-manager/app:1.2.4`, `ghcr.io/nginx-manager/nginx:1.2.4-nginx1.31.8`
- nginx: 1.31.8 (v1.2.3과 같음)
- 설치 묶음: [GitHub Release v1.2.4](https://github.com/nginx-manager/app/releases/tag/v1.2.4)의 `install.sh`, `nginx-manager.tar.gz`

이제 쓰지 않는 사이트를 화면에서 지울 수 있고, 사이트마다 그 사이트가 바뀐 버전만 모아 볼 수 있습니다. 멤버도 담당 사이트의 변경 이력을 봅니다. 가져온 원문 사이트의 로그도 로그 화면에서 읽고, 버전이 쌓여도 DB가 크게 늘지 않도록 저장 방식을 바꿨습니다.

## 사이트 지우기

- 사이트 화면 아래의 **사이트 삭제**를 누르면 확인 창을 거쳐 삭제 초안이 생기고, 사이트에 **삭제 대기** 표시가 붙습니다. 적용하면 사이트 파일(비밀번호 보호 파일 포함)이 빠지고 사이트도 목록에서 사라집니다.
- 한 번도 적용하지 않은 사이트는 바로 지워집니다. 적용하지 않은 변경이 남은 사이트는 먼저 적용하거나 버려야 지울 수 있습니다.
- 지운 사이트도 이전 버전으로 되돌리면 다시 살아납니다. 삭제는 감사 로그에 남습니다.
- 인증서 화면의 **발급된 인증서**에서도 쓰는 사이트가 없는 인증서를 지울 수 있습니다. 꺼 둔 사이트의 인증서는 더 이상 갱신하지 않습니다. 자세한 것은 사용 설명서 4장 "사이트 지우기"와 9장 "쓰지 않는 인증서 지우기"를 봅니다.

## 사이트별 변경 이력

- 사이트 화면의 **변경 이력**을 누르면 그 사이트 파일이 바뀐 버전(적용 실패 포함)만 모아 보입니다. 관리자는 변경 이력 화면에서 도메인으로 걸러 볼 수도 있습니다.
- 멤버도 담당 사이트의 변경 이력, 버전 내용, 비교를 볼 수 있습니다. 보이는 파일은 그 사이트 파일뿐이고, 되돌리기는 지금처럼 관리자만 합니다(사용 설명서 8장 "사이트별 이력").

## 원문 사이트 로그

- 가져온 원문 사이트는 server 블록에 적힌 `access_log`/`error_log` 경로를 읽어 로그 화면에 보여 줍니다. `/var/log/nginx` 밖이거나 변수를 쓴 경로처럼 읽을 수 없는 경우는 이유를 보여 줍니다.
- 관리자는 원문 사이트에 사이트별 로그 두 줄을 더하는 초안을 만들 수 있습니다.
- 크기를 넘어 밀려난 지난 로그 파일도 골라서 검색합니다. 자세한 것은 사용 설명서 11장을 봅니다.

## 버전이 차지하는 공간

- 버전마다 모든 파일 내용을 따로 저장하던 것을, 같은 내용은 한 번만 저장하도록 바꿨습니다. 모든 버전은 그대로 남고 되돌릴 수 있습니다.
- 갱신으로 밀려난 옛 인증서 디렉터리는 사이트나 초안이 쓰지 않으면 정리합니다. 그런 디렉터리를 쓰던 옛 버전으로 되돌리면 지금 인증서 경로로 바꿔 적용합니다(사용 설명서 8장 "버전이 차지하는 공간").

## 고친 문제

- 원문 사이트에서 Let's Encrypt 발급을 준비하면 인증 경로가 80 server 블록뿐 아니라 같은 파일의 다른 포트(예: `listen 9000`) server 블록에도 들어가던 문제를 고쳤습니다. 이제 80 포트를 듣는 블록에만 더하고, 인증서 도메인과 443 블록도 80 블록에서만 가져옵니다. 이미 다른 포트 블록에 들어간 인증 경로는 원문 편집기에서 지워도 됩니다.

## 업그레이드할 때

- `sudo /opt/nginx-manager/nm upgrade`로 manager만 올리면 됩니다. 에이전트 API 판은 그대로(1)라 nginx 이미지는 올리지 않아도 됩니다.
- 처음 시작할 때 버전 저장 방식을 옮기는 DB 마이그레이션을 하고, 비게 된 공간이 크면 DB를 한 번 압축(VACUUM)합니다. 버전이 많으면 첫 시작이 조금 오래 걸릴 수 있습니다. 업그레이드 전 백업은 지금처럼 `nm upgrade`가 만듭니다.
- `.env`에서 손볼 것은 없습니다.
