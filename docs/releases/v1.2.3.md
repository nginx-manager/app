# v1.2.3 — 원문 사이트에도 Let's Encrypt

- 날짜: 2026-10-30
- 이미지: `ghcr.io/nginx-manager/app:1.2.3`, `ghcr.io/nginx-manager/nginx:1.2.3-nginx1.31.8`
- nginx: 1.31.8 (v1.2.2와 같음)
- 설치 묶음: [GitHub Release v1.2.3](https://github.com/nginx-manager/app/releases/tag/v1.2.3)의 `install.sh`, `nginx-manager.tar.gz`

설정 파일 가져오기로 들어온 원문 사이트(폼에 없는 지시어가 있는 사이트)는 지금까지 관리도구에서 HTTPS를 켤 수 없었습니다. 이제 원문 사이트도 Let's Encrypt 인증서를 받고, 받은 인증서로 443 server 블록을 붙일 수 있습니다.

## 원문 사이트에 HTTPS 켜기 (관리자)

1. 사이트 화면의 **HTTPS 인증서**에서 **Let's Encrypt 인증서 발급받기**를 누릅니다. 인증서 화면의 **Let's Encrypt 인증서 받기** 목록에도 원문 사이트가 보입니다.
2. 80 server 블록에 인증 경로(`/.well-known/acme-challenge/`)가 없으면 더한 초안이 생깁니다. 적용하면 발급을 시작합니다. 도메인은 server_name에서 읽습니다(와일드카드 제외).
3. 발급되면 인증서 경로와 **443 server 블록 초안에 더하기**가 보입니다. 80 server 블록을 본떠 `listen 443 ssl`, `http2 on`, 인증서 경로를 넣은 블록을 더한 초안을 만듭니다.
4. **HTTP(80) 요청을 HTTPS로 넘기기**(기본 켬)를 켜 두면 80 server 블록은 listen·server_name·인증 경로와 `return 301 https://$host$request_uri;`만 남습니다. 인증 경로는 넘기지 않으므로 갱신이 계속 됩니다. 원문을 확인하고 적용합니다.
5. 갱신되면 원문의 인증서 경로는 저절로 새 경로로 바뀝니다.

원문의 나머지(업로드 크기, 프록시 헤더 등)는 그대로 둡니다. 자세한 것은 사용 설명서 5장 "원문 사이트에 HTTPS 켜기"를 봅니다.

## 그 밖에 바뀐 것

- 인증서 화면: **발급된 인증서**와 **발급 대기·실패** 탭으로 나눴고, 발급하지 못한 인증서를 지울 수 있습니다(확인 창을 거치며, 사이트나 관리 도메인이 쓰는 인증서는 지울 수 없습니다. 사용 설명서 9장).
- 변경 이력에서 두 버전을 비교할 때 고르는 칸을 **변경 전**과 **변경 후**로 나누고, 같은 버전이나 거꾸로 된 순서처럼 비교할 수 없는 선택은 막습니다(사용 설명서 8장).

## 업그레이드할 때

- `sudo /opt/nginx-manager/nm upgrade`로 manager만 올리면 됩니다. 에이전트 API 판은 그대로(1)라 nginx 이미지는 올리지 않아도 됩니다.
- `.env`에서 손볼 것은 없습니다.
