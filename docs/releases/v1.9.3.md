# v1.9.3 — 같은 서버의 앱으로 프록시하는 사이트가 연결되지 않던 문제

- 날짜: 2026-11-03
- 이미지: `ghcr.io/nginx-manager/app:1.9.3`, `ghcr.io/nginx-manager/nginx:1.9.3-nginx1.31.8`
- nginx: 1.31.8 (v1.9.2와 같음)
- 설치 묶음: [GitHub Release v1.9.3](https://github.com/nginx-manager/app/releases/tag/v1.9.3)의 `install.sh`, `nginx-manager.tar.gz`

새 기능 없이, 같은 서버에서 도는 앱을 사이트로 등록하면 502가 나던 문제를 고친 버전입니다.

## 고친 문제

- **프록시 대상을 `http://127.0.0.1:<포트>`로 적은 사이트가 연결되지 않음**: nginx는 컨테이너 안에서 돌기 때문에 `127.0.0.1`·`localhost`는 서버가 아니라 nginx 컨테이너 자신입니다. 같은 서버의 앱이라도 닿지 않아 502가 났는데, 화면 안내 문구가 오히려 `http://127.0.0.1:8080`을 예로 들고 있었습니다.
  - nginx 컨테이너에 서버(호스트)를 부르는 이름 `host.docker.internal`을 기본으로 넣었습니다(compose 파일의 `extra_hosts: host.docker.internal:host-gateway`).
  - 사이트 폼(프록시 대상, 백업 업스트림, 경로별 라우팅, PHP-FPM 주소)과 스트림 백엔드가 `127.0.0.1`·`localhost`·`0.0.0.0`·`::1`을 받지 않고, 왜 안 되는지와 `host.docker.internal`·서버 사설 IP·컨테이너 이름으로 적으라고 안내합니다.
  - 서버의 nginx 설정 파일을 폼 사이트로 가져올 때는 `127.0.0.1`·`localhost`를 `host.docker.internal`로 바꾸고, 미리 보기의 "폼으로 옮기면 바뀌는 점"에 보여 줍니다.
  - 화면 예시 문구를 `http://host.docker.internal:8080`으로 바꿨습니다.
- 사용 설명서 4장(사이트), 5장(가져오기), 6장(스트림)에 같은 서버의 앱을 적는 방법을, 13장(문제 해결)에 "사이트를 등록했는데 502가 나거나 연결되지 않을 때"를 더했습니다.

## 업그레이드할 때

- 업그레이드 도중에 쓰는 `nm`은 이전 버전의 것이라 두 번에 나눠 실행합니다. `sudo /opt/nginx-manager/nm upgrade`로 manager와 새 compose 파일을 받고, `sudo /opt/nginx-manager/nm upgrade --nginx`로 nginx를 다시 띄워야 `host.docker.internal`이 생깁니다. 그 전에 사이트에 `host.docker.internal`을 적으면 적용이 `host not found in upstream`으로 실패합니다.
- 이미 `127.0.0.1`로 만든 사이트는 그대로 렌더링되지만(그래서 여전히 연결되지 않습니다) 수정해서 저장하려면 주소를 바꿔야 합니다. 사이트 목록 검색에 `127.0.0.1`을 넣으면 찾을 수 있습니다.
- 백엔드 앱이 `127.0.0.1`에서만 연결을 받고 있으면 컨테이너에서 닿지 않습니다. `0.0.0.0`에서 받게 바꾸고, 밖에서 그 포트로 바로 들어오는 것은 방화벽으로 막습니다.
- 에이전트 API 판은 그대로(1)입니다. `.env`에서 손볼 것은 없습니다.
