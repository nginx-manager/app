# v1.6.0 — 사용자 지정 헤더, 대표 도메인으로 모으기, 사이트 복제

- 날짜: 2026-10-30
- 이미지: `ghcr.io/nginx-manager/app:1.6.0`, `ghcr.io/nginx-manager/nginx:1.6.0-nginx1.31.8`
- nginx: 1.31.8 (v1.5.0과 같음)
- 설치 묶음: [GitHub Release v1.6.0](https://github.com/nginx-manager/app/releases/tag/v1.6.0)의 `install.sh`, `nginx-manager.tar.gz`

Raw 설정으로 넘어가던 이유 두 가지(헤더 추가, `www` → 대표 도메인 이동)를 폼으로 옮기고, 비슷한 사이트를 빨리 만들 수 있게 사이트 복제를 더했습니다.

## 사용자 지정 헤더

- 사이트 옵션 **사용자 지정 헤더**에 줄마다 `이름: 값`을 적습니다(각각 20줄까지).
- **응답 헤더**는 모든 응답에 붙습니다(`add_header … always`). CORS(`Access-Control-Allow-Origin`), `Content-Security-Policy`, `X-Robots-Tag` 같은 헤더에 씁니다. 경로별 라우팅의 경로에도 붙고, 모든 사이트 유형에서 씁니다.
- **백엔드로 보낼 헤더**(리버스 프록시)는 백엔드 요청에 더합니다(`proxy_set_header`, gRPC는 `grpc_set_header`). `Host`를 적으면 기본값 `$host` 대신 그 값을 보내고, 값을 비우면(`X-Debug:`) 그 헤더를 넘기지 않습니다.
- 값에 `$host` 같은 nginx 변수를 쓸 수 있습니다. 큰따옴표와 역슬래시는 쓸 수 없고, `X-Real-IP`·`X-Forwarded-*`·`Upgrade`·`Connection`은 관리도구가 정합니다(사용 설명서 4장 "사용자 지정 헤더").

## 추가 도메인을 대표 도메인으로 보내기

- 추가 도메인 아래의 **추가 도메인을 대표 도메인으로 보내기**를 켜면 `www.example.com/a?b=1`은 `example.com/a?b=1`로 301 이동합니다. 리다이렉트 사이트를 따로 만들 필요가 없습니다.
- HTTPS 인증서가 있으면 `https://대표 도메인`으로 보냅니다. 인증서는 지금처럼 대표·추가 도메인을 한 인증서로 받고, 추가 도메인도 Let's Encrypt 발급 경로는 그대로 받습니다(사용 설명서 4장).

## 사이트 복제

- 폼 사이트 화면의 **복제**를 누르면 새 사이트 폼이 그 사이트의 유형·포트·대상·옵션으로 채워져 열립니다. 도메인만 적고 저장하면 됩니다.
- 도메인, 비밀번호 보호 사용자, 업로드 인증서는 옮기지 않습니다(HTTPS였다면 Let's Encrypt로 바뀝니다).

## 업그레이드할 때

- `sudo /opt/nginx-manager/nm upgrade`로 manager만 올리면 됩니다. 에이전트 API 판은 그대로(1)라 nginx 이미지는 올리지 않아도 됩니다.
- 새 설정은 사이트 옵션에 저장되므로 DB 마이그레이션은 없습니다. 기존 사이트의 설정 파일은 바뀌지 않습니다.
