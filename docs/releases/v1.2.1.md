# v1.2.1 — 관리 도메인 점검, 적용 오류 표시, Certbot 인증서 그대로 쓰기

- 날짜: 2026-10-30
- 이미지: `ghcr.io/nginx-manager/app:1.2.1`, `ghcr.io/nginx-manager/nginx:1.2.1-nginx1.31.8`
- nginx: 1.31.8 (v1.2.0과 같음)
- 설치 묶음: [GitHub Release v1.2.1](https://github.com/nginx-manager/app/releases/tag/v1.2.1)의 `install.sh`, `nginx-manager.tar.gz`

v1.2.0을 실제 서버에 설치하며 드러난 문제를 고쳤습니다. 관리 도메인을 잘못 적었을 때 바로 알려 주고, 인증서를 받으면 곧바로 HTTPS로 열리며, 적용이 실패하면 이유가 화면에 보입니다.

## 관리 도메인 점검(`nm check-domain`)

`.env`의 `NGINX_MANAGER_ADMIN_DOMAIN`이 DNS에 있는지, `http://도메인`이 이 서버의 nginx로 들어오는지 서버에서 확인합니다. `nm status`, `nm restart`, `nm up`(설치 직후 포함) 뒤에도 저절로 확인합니다.

- 도메인 오타(예: `example.net.com`)나 A 레코드가 없으면 "DNS에서 찾지 못했습니다"라고 알립니다.
- DNS는 있지만 다른 서버로 가거나 방화벽이 80을 막으면 "이 서버의 nginx로 들어오지 않습니다"라고 알립니다.
- 사용 설명서 13장에 브라우저에 보이는 것(404, `HTTPS certificate is not ready yet`)으로 원인을 가르는 표를 더했습니다.

## Certbot 인증서를 그대로 쓰기

서버의 Certbot이 받은 인증서를 쓰는 설정을 그대로 가져올 수 있습니다.

- `.env`의 `NGINX_MANAGER_IMPORT_ROOTS`에 `/etc/letsencrypt`를 더하고(예: `/home,/etc/letsencrypt`) `nm up`하면 두 컨테이너에 같은 경로로 읽기 전용으로 붙습니다. 이제 `.env`만 고쳐도 되고, `/etc` 아래 디렉터리(`/etc/nginx` 제외)도 붙일 수 있습니다.
- `nm import-root grant /etc/letsencrypt/live /etc/letsencrypt/archive`로 `600` 개인 키까지 컨테이너 사용자에게만 읽기를 줍니다. `nm import-root check`는 `live/`의 링크가 가리키는 파일까지 읽어 봅니다.
- 새 명령 `nm reload`: 설정을 검사하고 통과하면 nginx를 끊김 없이 다시 읽힙니다. Certbot 갱신 후 훅(`/etc/letsencrypt/renewal-hooks/deploy/`)에 넣습니다. 절차는 사용 설명서 5장 "Certbot 인증서를 그대로 쓰기"에 있습니다.

## 고친 문제

- 관리 도메인 인증서를 받은 뒤에도 최대 1분 동안 `HTTPS certificate is not ready yet`가 보이던 문제: 발급이 끝나면 바로 HTTPS로 바꿉니다.
- **검증 후 적용**을 눌러도 반응이 없어 보이던 문제: 결과가 화면 위쪽에 나와 보이지 않았습니다. 이제 결과로 화면이 옮겨 갑니다. 요청 자체가 실패하면(HTTP 오류, 연결 끊김) 버튼 옆에 이유가 보이고, 예상하지 못한 오류도 실패 카드와 로그로 남습니다.
- Certbot이 만든 설정을 가져오면 `/etc/letsencrypt/...` 파일이 컨테이너에 없어 적용할 때 문법 검증에서 실패하던 문제: 가져오기 미리 보기에서 컨테이너에 없는 파일을 알려 주고, 80 server만 가져와 관리도구에서 HTTPS를 켜는 방법을 안내합니다.

## 업그레이드할 때

- `sudo /opt/nginx-manager/nm upgrade`로 manager만 올리면 됩니다. nginx는 끊기지 않습니다. 에이전트 API 판은 그대로(1)라 nginx 이미지는 올리지 않아도 됩니다.
- `.env`에서 손볼 것은 없습니다.
