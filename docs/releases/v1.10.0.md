# v1.10.0 — 재부팅 뒤 업스트림 이름을 기다려 nginx 띄우기, 따로 깐 nginx 알림

- 날짜: 2026-11-08
- 이미지: `ghcr.io/nginx-manager/app:1.10.0`, `ghcr.io/nginx-manager/nginx:1.10.0-nginx1.31.8`
- nginx: 1.31.8 (v1.9.3과 같음)
- 설치 묶음: [GitHub Release v1.10.0](https://github.com/nginx-manager/app/releases/tag/v1.10.0)의 `install.sh`, `nginx-manager.tar.gz`

서버를 재부팅한 뒤 사이트 하나의 설정 때문에 모든 사이트가 내려가 있던 문제를 막습니다. 여러 팀이 한 서버를 함께 쓰는 운영에서 실제로 겪은 장애에서 나왔습니다.

## 재부팅 뒤 업스트림 이름을 잠시 기다렸다가 nginx를 띄움

nginx는 설정 파일 하나라도 업스트림 이름(다른 컨테이너 이름, `extra_hosts`로 준 이름 등)을 풀지 못하면 아무 사이트도 띄우지 않습니다. 서버를 재부팅하면 그 이름의 컨테이너가 nginx보다 늦게 뜨는 일이 흔한데, 지금까지는 그 순간 시작 검사가 실패해 nginx가 "설정이 고쳐질 때까지" 내려간 채로 남았습니다. 이름이 곧 풀려도 누군가 **nginx 시작**을 누를 때까지 모든 사이트가 응답하지 않았습니다.

- 이제 nginx 컨테이너가 시작할 때 `host not found in upstream`으로만 실패하면, `NGINX_STARTUP_RESOLVE_WAIT`초(기본 180) 동안 5초마다 다시 검사합니다. 이름이 풀리면 nginx를 띄우고 시작 검사 기록도 통과로 바꿉니다.
- 다른 오류(모르는 지시어, 문법 오류 등)는 기다려도 고쳐지지 않으므로 지금처럼 바로 내려 두고 대시보드에 문제 파일과 줄을 보여 줍니다.
- 기다리는 것은 컨테이너가 막 시작했을 때뿐입니다. 관리 화면의 **nginx 시작**은 지금처럼 바로 결과를 보여 줍니다.
- 기다리지 않게 하려면 `compose.override.yml`의 nginx `environment`에 `NGINX_STARTUP_RESOLVE_WAIT: "0"`을 줍니다.

## 따로 깐 nginx가 부팅 때 뜨면 알려 줌

서버에 apt 등으로 깐 nginx(`nginx.service`)가 부팅 때 자동으로 뜨게 되어 있으면, 재부팅 뒤 nginx manager보다 먼저 80/443을 잡아 모든 사이트가 그 nginx로 갑니다(인증서가 다른 사이트 것으로 나오거나 502).

- `nm status`, `nm upgrade`, 설치 마지막에 이런 nginx를 찾으면 끄는 방법(`sudo systemctl disable --now nginx && sudo systemctl mask nginx`)과 함께 알려 줍니다.
- 사용 설명서 1장(포트)과 13장 "서버를 재부팅한 뒤 모든 사이트가 응답하지 않을 때"에 확인 순서를 더했습니다. 학교·회사 망의 웹 필터가 80을 막아 차단 안내 페이지가 보이는 경우도 함께 적었습니다.

## 업그레이드할 때

- 업그레이드 도중에 쓰는 `nm`은 이전 버전의 것이라 두 번에 나눠 실행합니다. `sudo /opt/nginx-manager/nm upgrade`로 manager와 새 `nm`을 받고, `sudo /opt/nginx-manager/nm upgrade --nginx`로 nginx 이미지를 올려야 재부팅 때 기다리는 동작이 들어갑니다.
- 에이전트 API 판은 그대로(1)입니다. `.env`에서 손볼 것은 없습니다.
