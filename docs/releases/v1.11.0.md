# v1.11.0 — 사이트 담당자도 추가 지시어 쓰기, 관리자 전용 지시어는 요청으로

- 날짜: 2026-11-13
- 이미지: `ghcr.io/nginx-manager/app:1.11.0`, `ghcr.io/nginx-manager/nginx:1.11.0-nginx1.31.8`
- nginx: 1.31.8 (v1.10.0과 같음)
- 설치 묶음: [GitHub Release v1.11.0](https://github.com/nginx-manager/app/releases/tag/v1.11.0)의 `install.sh`, `nginx-manager.tar.gz`

사이트를 맡은 멤버가 `proxy_request_buffering off;` 같은 지시어 한 줄 때문에 관리자에게 부탁하지 않아도 되게 했습니다. 서버 전체 운영에 영향을 줄 수 있는 지시어는 지금처럼 관리자만 넣고, 멤버는 화면에서 바로 관리자에게 요청합니다.

## 담당자도 추가 지시어를 고침

- 사이트 옵션의 **추가 지시어**(server 블록 끝에 덧붙일 nginx 지시어)를 이제 관리자뿐 아니라 그 사이트의 담당 멤버도 고치고 지울 수 있습니다. 칸 이름의 "(관리자)" 표시를 뺐습니다.
- 멤버가 새로 만드는 사이트는 그 멤버가 담당자가 되므로 처음부터 추가 지시어를 넣을 수 있습니다. 담당하지 않는 사이트는 지금처럼 열거나 저장할 수 없습니다(404).

## 쓸 수 있는 지시어 목록

- 칸 아래 **쓸 수 있는 지시어**를 펼치면 자주 쓰는 지시어 13개(`client_body_timeout`, `proxy_request_buffering`, `proxy_buffering`, `proxy_read_timeout`, `large_client_header_buffers`, `server_tokens`, 상태 확인 `location` 등)와 하는 일이 나옵니다. **넣기**를 누르면 칸 끝에 한 줄로 더해집니다.
- 관리자만 넣는 지시어와 그 규칙도 함께 보입니다.

## 관리자 전용 지시어는 관리자에게 요청

- 서버의 파일 경로를 쓰는 지시어(`root`, `alias`, `include`, `access_log`, `error_log`, `ssl_certificate`, 이름이 `_path`·`_file`·`_certificate`로 끝나는 것 등), 다른 사이트의 포트·도메인을 가로챌 수 있는 지시어(`listen`, `server_name`), 코드를 돌리는 지시어(`perl`·`js_`·`lua`로 시작하는 것 등)는 관리자만 넣습니다. `location`·`if` 블록 안에 있어도 찾습니다.
- 멤버가 이런 지시어를 새로 적어 저장하면 저장하지 않고 막힌 지시어를 알려 줍니다. 관리자가 이미 넣어 둔 지시어는 멤버가 다른 줄을 고쳐 저장해도 그대로 둘 수 있습니다.
- 막혔을 때 **관리자에게 요청**을 누르면 칸에 적은 내용 그대로 요청이 갑니다. 관리자는 사이트 목록 위의 **검토할 추가 지시어 요청**이나 사이트 화면의 **추가 지시어 요청** 카드에서 **반영**하거나 **거절**합니다. 반영하면 추가 지시어가 바뀐 초안이 생기므로 적용 화면에서 diff를 보고 적용합니다.
- 요청·반영·거절은 감사 로그(**추가 지시어 요청**)에 남고, 요청은 알림 채널에도 갑니다. 알림 설정에 **추가 지시어 요청** 종류가 생겼습니다(받을 알림을 따로 고른 채널은 켜야 받습니다).

## 고친 문제

- `LocaleTest`를 혼자 돌리면 최초 설정 화면으로 넘어가 실패하던 테스트 순서 의존을 없앴습니다(동작 변화 없음).

## 업그레이드할 때

- `sudo /opt/nginx-manager/nm upgrade`로 manager만 올리면 됩니다. 시작할 때 DB에 요청 표(`directive_request`)가 더해집니다. nginx 이미지와 에이전트 API 판(1)은 그대로이고, `.env`에서 손볼 것은 없습니다.
