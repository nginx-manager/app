# v1.9.2 — nginx 이미지 업그레이드 사전 검사 수정

- 날짜: 2026-10-31
- 이미지: `ghcr.io/nginx-manager/app:1.9.2`, `ghcr.io/nginx-manager/nginx:1.9.2-nginx1.31.8`
- nginx: 1.31.8 (v1.9.1과 같음)
- 설치 묶음: [GitHub Release v1.9.2](https://github.com/nginx-manager/app/releases/tag/v1.9.2)의 `install.sh`, `nginx-manager.tar.gz`

새 기능 없이 서버 설치 묶음의 `nm` 버그를 고친 버전입니다.

## 고친 문제

- **`nm upgrade --nginx`가 멀쩡한 설정을 거부함**: 새 nginx 이미지로 바꾸기 전에 지금 설정을 검사하는데, 이 검사를 compose 네트워크 밖의 임시 컨테이너에서 돌렸습니다. 그래서 `compose.override.yml`의 `extra_hosts`·`dns`나 compose 네트워크로만 풀리는 업스트림 이름(예: `server minio1.internal:9000;`)을 찾지 못해 `host not found in upstream`으로 멈췄습니다. 이제 검사가 지금 돌고 있는 nginx 컨테이너의 네트워크를 함께 써서 그 컨테이너와 똑같이 이름을 풉니다.
- 사용 설명서 13장(문제 해결)에 "host not found in upstream"으로 멈출 때 확인할 것과 고치는 방법을 더했습니다.

## 업그레이드할 때

- 업그레이드 도중에 쓰는 `nm`은 이전 버전의 것이라, 두 번에 나눠 실행합니다. 먼저 `sudo /opt/nginx-manager/nm upgrade`로 manager와 새 `nm`을 받고, 그다음 `sudo /opt/nginx-manager/nm upgrade --nginx`로 nginx 이미지를 올립니다.
- 에이전트 API 판은 그대로(1)입니다. `.env`에서 손볼 것은 없습니다.
