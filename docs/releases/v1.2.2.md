# v1.2.2 — 권한 문제로 관리 화면이 뜨지 않던 문제

- 날짜: 2026-10-30
- 이미지: `ghcr.io/nginx-manager/app:1.2.2`, `ghcr.io/nginx-manager/nginx:1.2.2-nginx1.31.8`
- nginx: 1.31.8 (v1.2.1과 같음)
- 설치 묶음: [GitHub Release v1.2.2](https://github.com/nginx-manager/app/releases/tag/v1.2.2)의 `install.sh`, `nginx-manager.tar.gz`

서버에서 `sudo`로 `data/conf` 아래에 디렉터리를 만들고 설정을 적용하면, 관리도구가 그 root 소유 디렉터리에 쓰지 못해 적용이 500으로 끝났습니다. 그때 남은 복구 기록 때문에 다음 시작부터 manager가 뜨지 않았습니다(업그레이드하면 "되돌렸습니다"로 끝남). nginx와 사이트는 영향이 없었습니다.

## 고친 것

- manager가 시작할 때 설정·로그·공유 디렉터리의 소유자를 컨테이너 사용자(UID 10101)로 맞춥니다. 전에는 nginx 컨테이너가 다시 뜰 때만 맞췄습니다. 그 안에 따로 붙인 읽기 전용 경로(`nm import-root`)는 건드리지 않습니다.
- 끊긴 적용을 되돌리다 실패해도 관리 화면은 뜹니다. 실패를 감사 로그에 남기고, 다음 시작 때 다시 되돌립니다.
- 적용 중 쓰기에 실패해 되돌리지도 못하면 복구 기록을 남겨 다음 시작 때 되돌립니다.
- 관리도구가 설정 파일에 쓸 수 없어 적용이 실패하면, 어느 경로인지와 `sudo /opt/nginx-manager/nm restart`로 고치는 방법을 화면에 보입니다.
- 사용 설명서 13장에 "관리 화면이 뜨지 않을 때"와 "쓸 수 없어 적용하지 못했습니다"를 더했습니다.

## 업그레이드할 때

- `sudo /opt/nginx-manager/nm upgrade`로 manager만 올리면 됩니다. 에이전트 API 판은 그대로(1)라 nginx 이미지는 올리지 않아도 됩니다.
- v1.2.1 이하에서 manager가 뜨지 않는 상태라면 먼저 `sudo chown -R 10101:10101 /opt/nginx-manager/data/conf` 뒤 `sudo /opt/nginx-manager/nm restart`로 살린 다음 올립니다.
- `.env`에서 손볼 것은 없습니다.
