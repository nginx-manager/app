# v1.5.0 — 경로별 라우팅, 백업 업스트림·keepalive, 점검 모드

- 날짜: 2026-10-30
- 이미지: `ghcr.io/nginx-manager/app:1.5.0`, `ghcr.io/nginx-manager/nginx:1.5.0-nginx1.31.8`
- nginx: 1.31.8 (v1.4.0과 같음)
- 설치 묶음: [GitHub Release v1.5.0](https://github.com/nginx-manager/app/releases/tag/v1.5.0)의 `install.sh`, `nginx-manager.tar.gz`

폼 사이트에서 Raw 설정으로 넘어가게 만들던 흔한 구성 세 가지를 폼으로 옮겼습니다. 경로마다 다른 백엔드·디렉터리로 보내고, 업스트림에 백업 서버·장애 판정·keepalive를 정하고, 배포 중에는 점검 모드로 안내 페이지를 보여 줍니다.

## 경로별 라우팅 (location)

- 사이트 옵션 **경로별 라우팅**에 줄마다 `경로 대상`을 적습니다. 예: `/api/ http://127.0.0.1:8080/`, `/files/ /srv/uploads`.
- 대상이 `http(s)://` 주소면 그 경로를 프록시하고(`proxy_pass`, 주소 끝에 경로를 적으면 location 경로를 떼고 넘김), `/`로 시작하는 디렉터리면 파일을 바로 줍니다(`alias`).
- 경로마다 `location ^~`가 생기고, 접근 제한·Basic 인증·외부 인증·속도 제한·보안 헤더가 똑같이 걸립니다.
- 리버스 프록시와 정적 파일 사이트에서 씁니다. gRPC 프록시와 PHP 사이트에는 쓸 수 없습니다(사용 설명서 4장 "경로별 라우팅").

## 백업 업스트림, 장애 판정, keepalive

- 리버스 프록시 세부 설정에 **백업 업스트림**(주 업스트림이 모두 실패할 때만 받는 서버, `backup`), **장애 판정**(`max_fails`, `fail_timeout`), **keepalive 연결 수**가 생겼습니다.
- 하나라도 쓰면 업스트림이 하나여도 `upstream` 블록으로 묶습니다. keepalive를 쓰면 `Connection` 헤더를 비워 연결을 다시 쓰고, WebSocket과도 함께 씁니다.
- 분산 방식이 ip_hash면 백업 업스트림을 쓸 수 없습니다(nginx가 받지 않습니다). gRPC 업스트림에도 같은 설정을 씁니다.

## 점검 모드

- 사이트 옵션 **점검 모드**를 켜고 적용하면 방문자는 `503`과 안내 문구(비우면 기본 문구)를 보고, `Retry-After: 600`이 함께 갑니다.
- **점검 중에도 들어올 수 있는 주소**(작업자 IP·CIDR)는 평소처럼 사이트를 봅니다. Let's Encrypt 인증서 발급 경로는 막지 않습니다.
- 점검 중인 사이트는 사이트 목록과 사이트 화면에 **점검 중**으로 보입니다(사용 설명서 4장 "점검 모드").

## 업그레이드할 때

- `sudo /opt/nginx-manager/nm upgrade`로 manager만 올리면 됩니다. 에이전트 API 판은 그대로(1)라 nginx 이미지는 올리지 않아도 됩니다.
- 새 설정은 사이트 옵션에 저장되므로 DB 마이그레이션은 없습니다. 기존 사이트의 설정 파일은 바뀌지 않습니다.
