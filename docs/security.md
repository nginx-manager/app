# 보안 점검 (T081)

2026-10-13, 007-upgrade-safety 기준으로 확인한 내용. 프로세스 실행 항목은 2026-10-14 컨테이너 분리에 맞춰 고쳤다.

## 프로세스 실행

- nginx와 관리도구는 다른 컨테이너에서 돈다. 관리도구 컨테이너에는 nginx 실행 파일이 없고, 외부 프로세스를 만들지 않는다(`ProcessBuilder`·`Runtime.exec`를 쓰지 않는다).
- nginx 명령은 nginx 컨테이너 안의 에이전트(`agent/`, Go)만 실행한다. 에이전트가 실행하는 명령은 고정된 인자뿐이다: `nginx -t`, `nginx -s reload`, `nginx -s reopen`, `nginx -V`, `s6-svc -u <서비스 디렉터리>`. 요청에서 받는 값은 대기 시간(`?timeout=`, 최대 60초)뿐이고 명령 인자로 들어가지 않는다. 셸을 거치지 않는다.
- 관리도구에 Docker 소켓을 넘기지 않는다. 관리도구가 nginx에 할 수 있는 일은 에이전트 API의 위 명령뿐이다.
- 에이전트는 `/healthz`(버전만 알려 줌)를 뺀 모든 요청에 토큰(`Authorization: Bearer`)을 요구하고 상수 시간으로 비교한다. 토큰은 에이전트가 처음 뜰 때 공유 볼륨(`/var/lib/nginx-manager/agent/token`, 0640)에 무작위 256비트로 만든다. `NGINX_AGENT_TOKEN`·`NGINX_RUNTIME_AGENT_TOKEN`으로 직접 정할 수도 있다.
- 에이전트 포트(7070)는 호스트에 열지 않고 같은 Docker 네트워크에서만 쓴다. nginx 사이트가 에이전트(7070)·상태 확인(8081)·관리 화면(9000, `manager:9000`)으로 프록시하거나 그 포트로 listen하지 못하게 폼 검증에서 막는다.
- 두 컨테이너의 프로세스는 같은 비루트 UID(10101, `nginxm`)로 돈다. 에이전트가 nginx에 할 수 있는 일은 같은 사용자로서의 신호와, s6 제어 권한(`s6-svperms -G nginxm`)으로 nginx 서비스를 올리는 것뿐이다. 관리도구 컨테이너는 `/data` 소유자를 맞출 때만 루트로 시작하고 바로 `setpriv`로 내려간다.

## 파일 경로

- 설정 파일은 설정 루트 아래 상대 경로만 받는다(`ConfigFileStore`가 정규화 후 루트 밖이면 거절).
- 인증서 디렉터리 이름은 `CertificateFiles.safeName`(소문자·숫자·`.`·`-`, `.`으로 시작 불가)으로만 만든다.
- 로그는 사이트 도메인(폼 검증을 거친 값)으로만 경로를 만들고, `LogFiles`가 로그 디렉터리 밖이면 거절한다.

## 비밀 값

- 비밀번호는 해시로만 저장하고 로그·감사 로그에 남기지 않는다.
- 개인 키(업로드·ACME 계정·발급)는 파일로만 저장하고 권한을 600으로 둔다. 화면에 다시 보이지 않고, 업로드 오류 메시지에 키 내용을 넣지 않는다.
- 웹훅 URL은 토큰을 품는 경우가 많아, 발송 실패 로그에는 스킴과 호스트만 남긴다. 화면(ADMIN 전용 알림 설정)에는 전체가 보인다.
- 애플리케이션 로그를 훑어 비밀번호·키·토큰을 남기는 곳이 없음을 확인했다.
- 사이트 비밀번호 보호(auth_basic) 비밀번호는 폼에서 받는 즉시 `{SSHA}` 해시로 바꿔 `htpasswd/<도메인>` 파일에만 쓴다. 화면에는 사용자 이름만 다시 보이고, 비밀번호를 비워 두면 기존 해시를 그대로 쓴다. nginx가 요청마다 검사하므로 느린 해시(bcrypt)는 쓰지 않는다. 해시 파일도 설정 파일이라 버전 이력·diff에 해시가 보인다. 이력은 관리자만 보지만(v1.2.0부터), 이 해시가 노출되어도 될 만큼 긴 비밀번호(8자 이상을 받는다)를 쓰게 한다.

## 웹

- 모든 화면은 로그인 필요, 변경 요청은 CSRF 토큰 필요. 역할별 접근은 `RoleAccessTest`가 경로 표(contracts/http-routes.md)대로 검증한다.
- 로그 내용처럼 외부에서 들어온 문자열은 Thymeleaf가 이스케이프하고, 실시간 로그는 `textContent`로만 붙인다.
- actuator는 `health`만 열고 상세를 숨긴다.
- 로그인 실패가 이어지면 계정을 잠근다(감사 로그 `ACCOUNT_LOCKED`).

## 운영할 때 알아 둘 것

- 관리 화면(9000)은 HTTP로 뜬다. 설치 묶음(v1.2.0, 008)은 9000을 `127.0.0.1`에만 열고, 인터넷에서는 관리 도메인(`NGINX_MANAGER_ADMIN_DOMAIN`)으로만 들어오게 한다. 관리 도메인 설정은 Let's Encrypt 인증서를 받기 전에는 관리 화면을 열지 않고(503), 받은 뒤에는 HTTP를 HTTPS로 넘기며 HSTS를 붙인다. 관리 화면은 nginx가 넘긴 `X-Forwarded-Proto`(사설망 주소의 프록시만 믿는다)로 HTTPS 요청을 알아보고 그 요청의 세션 쿠키에 `Secure`를 붙인다. `NGINX_MANAGER_ADMIN_ALLOW`로 접속 주소를 nginx 단계에서 좁힐 수 있다.
- 관리 도메인 설정 파일(`conf.d/sites/_nginx-manager-admin.conf`)은 관리도구만 쓴다. 원문 편집기의 저장·삭제는 403이고, 같은 도메인으로 사이트를 만들 수 없다. 사이트 폼·스트림의 `manager:9000` 차단 규칙은 그대로다.
- 직접 compose로 띄워 HTTPS 프록시 뒤에 두면 `SERVER_SERVLET_SESSION_COOKIE_SECURE=true`로 세션 쿠키를 HTTPS 전용으로 만든다.
- `.env`(SMTP 비밀번호 등)와 `nm backup`의 백업 파일(개인 키, DB 포함)은 권한 600으로 만든다. 백업 파일을 서버 밖으로 옮길 때도 같은 수준으로 보관한다.
- 업그레이드·백업은 호스트의 `nm`이 Docker로 한다. 관리도구 컨테이너에는 여전히 Docker 소켓을 주지 않는다.
- 스트림 화면은 관리용 포트(80, 443, 7070, 8081, 9000)로 받거나, 에이전트·관리 화면 주소로 넘기는 설정을 거절한다. 원문 편집기는 `certs/`, `htpasswd/` 아래에 새 파일을 만들지 못하고 `nginx.conf`, `mime.types`는 지우지 못한다.
- 알림 웹훅은 관리자가 정한 URL로 서버가 요청을 보낸다(내부망 주소도 가능). 관리자 계정을 신뢰할 수 있는 사람에게만 준다.
- 화면에 인라인 이벤트 처리기(`onchange`)가 있어 Content-Security-Policy는 아직 걸지 않았다. 기본 보안 헤더(X-Frame-Options, X-Content-Type-Options 등)는 Spring Security 기본값을 쓴다.
