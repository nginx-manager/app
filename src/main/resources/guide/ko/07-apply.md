# 7. 적용

사이트·스트림·설정 파일 화면에서 저장한 변경은 모두 **초안**입니다. 초안은 **적용** 화면에서 반영해야 nginx에 적용됩니다(편집자부터). 메뉴의 적용 옆 숫자가 적용 대기 중인 초안 수입니다.

## 바뀔 내용 확인

<p align="center"><img src="images/apply.png" alt="파일마다 diff가 보이는 적용 화면" width="860"></p>

- 바뀔 파일마다 diff가 보입니다. `-` 줄은 빠지는 내용, `+` 줄은 더해지는 내용입니다.
- 파일 이름 옆에 더한 줄·뺀 줄 수(예: `+17 −0`)가 보이고, 파일마다 diff를 접고 펼 수 있습니다.
- 삭제하는 파일에는 **삭제** 표시가 붙습니다.
- 원하지 않는 초안은 **초안 버리기**로 버립니다. 버린 초안은 서버에 아무 영향이 없습니다.

## 검증 후 적용

1. **변경 메모**(선택)를 적습니다. 예: `app 백엔드 포트 변경`. 이력에 함께 남아 나중에 무엇을 왜 바꿨는지 찾을 때 도움이 됩니다.
2. **검증 후 적용**을 누릅니다.
3. 관리도구가 다음 순서로 진행합니다.
   1. `nginx -t`로 문법을 검사합니다.
   2. 통과하면 nginx를 reload합니다(연결을 끊지 않는 무중단 반영).
   3. reload 뒤 nginx가 정상인지 확인합니다.
4. 결과가 화면에 나타나고, 성공하면 새 버전 번호로 [이력](08-versions.md)에 남습니다.

<p align="center"><img src="images/apply-result.png" alt="적용 성공 결과" width="860"></p>

## 결과별로 할 일

| 결과 | 뜻 | 할 일 |
| --- | --- | --- |
| 적용했습니다 | 문법 검증 → reload → 상태 확인을 모두 통과했습니다. | 없음 |
| 문법 검증에 실패해 반영하지 않았습니다 | 서버의 설정은 그대로입니다. 문제의 파일과 줄이 보입니다. | 해당 사이트나 파일을 고친 뒤 다시 적용합니다. 이번 초안이 바꾸지 않은 파일이 문제라면 따로 표시됩니다. |
| 반영 후 nginx 상태가 나빠 직전 설정으로 되돌렸습니다 | 포트 충돌처럼 `nginx -t`가 못 잡고 reload에서야 드러난 문제입니다. 서버는 직전 설정으로 돌아갔습니다. | 원인(예: 다른 곳에서 쓰는 포트)을 고친 뒤 다시 적용합니다. 실패 기록도 이력에 남습니다. |
| 적용하지 못했습니다 | nginx 컨테이너에 연결하지 못했습니다. 서버 설정과 초안은 그대로입니다. | nginx 컨테이너가 돌고 있는지 확인한 뒤 다시 적용합니다. |
| reload는 하지 않았습니다 | nginx가 멈춰 있어서 문법 검증만 하고 설정을 반영했습니다. | [대시보드](03-dashboard.md)에서 **nginx 시작**을 누릅니다. |

## 알아 둘 것

- 적용은 한 번에 하나씩만 진행됩니다. 적용 중에 다른 사람이 저장하려 하면 "지금 설정을 적용하는 중입니다" 안내가 나오니, 끝난 뒤 다시 저장합니다.
- 두 사람이 같은 사이트를 동시에 고치면 나중에 저장한 사람에게 "다른 사람이 먼저 저장했습니다" 안내가 나옵니다. 화면을 새로 고쳐 최신 내용을 확인한 뒤 다시 저장합니다.
- 적용 도중 관리도구가 멈추면 다음 시작 때 진행 중이던 적용을 되돌립니다.
