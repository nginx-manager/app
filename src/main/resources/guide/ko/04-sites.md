# 4. 사이트

사이트는 도메인 하나로 받는 HTTP(S) 서비스입니다. 사이트 하나가 `conf.d/sites/<도메인>.conf` 설정 파일 하나가 됩니다. 폼으로 만들고, 폼에 없는 설정은 Raw 편집기로 고칩니다.

## 사이트 목록

**사이트** 메뉴에서 사이트를 봅니다. 관리자에게는 모든 사이트가, 멤버에게는 본인이 담당한 사이트만 보입니다.

| 칸 | 내용 |
| --- | --- |
| 도메인 | 대표 도메인. 누르면 사이트 화면으로 갑니다. |
| 유형 | 프록시, 정적, 리다이렉트, PHP, Raw 설정 |
| 대상 | 프록시는 백엔드 주소, 정적은 document root, 리다이렉트는 리다이렉트 URL, PHP는 PHP-FPM 주소 |
| 포트 | HTTP 포트. HTTPS를 켠 사이트는 옆에 HTTPS가 붙습니다. |
| 상태 | 활성/비활성, 적용하지 않은 변경이 있으면 적용 대기, 삭제가 적용 대기 중이면 삭제 대기 |
| 담당자 | 사이트를 맡은 멤버. 비어 있으면 **담당자 없음**이고 관리자만 봅니다. 관리자에게만 보이는 칸입니다. |

v1.7.0부터 목록 위의 **검색**에 도메인, 백엔드 주소, 문서 루트의 일부를 적으면(대소문자 구분 없음) 맞는 사이트만 봅니다. 예를 들어 `10.0.0.21`을 적으면 그 백엔드를 쓰는 사이트가 모두 나옵니다. **상태**로 활성, 비활성, 적용 대기, 점검 중인 사이트만 볼 수도 있습니다. 검색 조건은 주소에 남아 새로고침하거나 주소를 공유해도 그대로이고, **지우기**로 처음 목록으로 돌아갑니다.

관리자는 같은 줄의 **담당자**에서 한 사람을 고르거나 **담당자 없음**을 골라 그 사이트만 봅니다. 검색과 함께 쓸 수 있습니다.

위의 **사이트 추가**로 새 사이트를, **설정 파일 가져오기**로 쓰던 설정 파일을 사이트로 등록합니다([5장](05-import.md), 관리자). 멤버가 만든 사이트는 그 멤버가 담당합니다.

### 공통 항목

| 항목 | 설명 |
| --- | --- |
| 도메인 | 이 사이트로 받을 대표 도메인(예: `app.example.com`). 설정·로그 파일 이름에도 쓰여 저장한 뒤에는 바꿀 수 없습니다. 와일드카드(`*.example.com`)도 됩니다. |
| 추가 도메인 | 같은 사이트로 받을 다른 이름(예: `www.app.example.com`). 공백이나 쉼표로 구분합니다. Let's Encrypt 인증서에도 함께 들어갑니다. **추가 도메인을 대표 도메인으로 보내기**를 켜면 추가 도메인은 내용을 보여 주지 않고 대표 도메인으로 301 이동합니다([아래](#추가-도메인을-대표-도메인으로-보내기)). |
| 유형 | 리버스 프록시, 정적 파일, 리다이렉트, PHP 중 하나. 고른 유형의 항목만 폼에 보입니다. |
| HTTP 포트 | 보통 80. 여러 사이트가 같은 포트를 써도 도메인으로 구분합니다. 443, 7070, 8081, 9000은 쓸 수 없습니다. |
| HTTPS | 사용 안 함, Let's Encrypt, 업로드한 인증서 중 하나([아래](#https)) |

### 리버스 프록시

요청을 뒤에 있는 애플리케이션 서버로 넘깁니다.

- **프록시 대상**: 백엔드 주소를 `http://호스트:포트` 형식으로 적습니다(예: `http://10.0.0.11:8080`). 둘 이상이면 줄마다 하나씩 적고(최대 32개), 모두 같은 `http`/`https`와 같은 경로여야 합니다.
- **프록시 세부 설정**(펼쳐서 정함)
  - **WebSocket 연결 넘기기**: 채팅·실시간 알림처럼 WebSocket을 쓰는 앱이면 켭니다.
  - **연결 타임아웃 / 응답 타임아웃**: 비우면 60초. WebSocket이나 오래 걸리는 요청은 응답 타임아웃을 길게(예: 3600) 잡습니다.
  - **백엔드가 여럿일 때 로드 밸런싱 방식**: 차례대로(기본), 연결이 가장 적은 백엔드로, 같은 클라이언트 IP는 같은 백엔드로. 로그인 세션을 서버 메모리에 두는 앱이면 마지막 방식을 고릅니다.
- 관리 화면(9000)이나 nginx 컨테이너의 관리용 포트(7070, 8081)로는 프록시할 수 없습니다.
- **백업 업스트림·장애 판정·keepalive**(v1.5.0부터, 프록시 세부 설정): **백업 업스트림**은 평소에는 쉬다가 위 업스트림이 모두 실패했을 때만 요청을 받습니다(점검용 서버, 다른 리전). 위 업스트림과 같은 `http`/`https`와 경로로 적고, 분산 방식이 ip_hash면 쓸 수 없습니다. **장애 판정**은 제외 시간(비우면 10초) 안에 실패 횟수(비우면 1)만큼 실패한 업스트림을 그 시간 동안 빼 둡니다(`max_fails`, `fail_timeout`). **keepalive 연결 수**를 정하면 업스트림 연결을 끊지 않고 다시 써서 요청이 많을 때 지연과 부하가 줄어듭니다. 셋 중 하나라도 쓰면 업스트림이 하나여도 `upstream` 블록으로 묶습니다.
- **gRPC 서버**(v1.4.0부터): 업스트림을 `grpc://호스트:포트`(TLS면 `grpcs://`)로 적으면 `proxy_pass` 대신 `grpc_pass`로 넘기고, HTTP 포트에서도 HTTP/2(h2c)로 받습니다. 다만 평문(h2c)은 nginx가 그 포트의 기본 서버 설정으로 HTTP/2 여부를 정하므로, 80처럼 다른 사이트와 함께 쓰는 포트가 아니라 이 사이트만 쓰는 HTTP 포트(예: 8086)를 따로 주세요. 경로는 적지 않고, 여럿이면 모두 같은 스킴이어야 합니다. 타임아웃은 `grpc_connect_timeout`·`grpc_read_timeout`이 되고, WebSocket과 프록시 캐시는 쓰지 않습니다. 브라우저가 아닌 gRPC 클라이언트는 보통 HTTPS(443)로 붙으므로 HTTPS를 켜 두세요.

### 정적 파일

서버 폴더의 파일을 그대로 내보냅니다.

- **document root**: 내보낼 폴더의 절대 경로(예: `/usr/share/nginx/html`). 주소가 폴더를 가리키면 그 안의 `index.html`을 보여 줍니다. 파일은 nginx 컨테이너 안에 있어야 하므로, 호스트 폴더라면 compose에서 nginx 서비스에 마운트합니다.
- 관리도구 데이터나 인증서 키가 있는 폴더는 document root로 쓸 수 없습니다.

### 리다이렉트

모든 요청을 다른 주소로 넘깁니다(도메인 이전 등).

- **리다이렉트 URL**: `http://`나 `https://`로 시작하는 주소(예: `https://new.example.com`)
- **응답 코드**: 301 영구 이동, 302 임시 이동, 307·308(POST 같은 메서드 유지)
- **요청 경로와 쿼리를 그대로 붙이기**: 켜면 `/a?b=1` 요청을 `리다이렉트 URL/a?b=1`로 넘깁니다.

### PHP (PHP-FPM)

WordPress, Laravel 같은 PHP 사이트입니다(v1.4.0부터). document root의 파일을 서빙하면서 `.php` 요청은 PHP-FPM으로 넘깁니다.

- **document root**: 정적 파일과 같은 규칙의 절대 경로(예: `/var/www/blog`). 주소가 디렉터리를 가리키면 `index.php`, 없으면 `index.html`을 보여 줍니다.
- **PHP-FPM 주소**: `127.0.0.1:9000`, `php-fpm:9000`처럼 호스트:포트, 또는 `unix:/run/php/php8.3-fpm.sock`처럼 소켓. 하나만 적습니다.
- 없는 경로는 `index.php`로 넘깁니다(`try_files $uri $uri/ /index.php?$query_string`). 워드프레스 고유 주소, 라라벨 라우팅이 그대로 됩니다.
- 접근 제한과 Basic 인증, 속도 제한은 `.php` 요청에도 똑같이 걸립니다.
- PHP-FPM은 nginx와 **같은 경로로** document root를 봐야 합니다. nginx는 `SCRIPT_FILENAME`에 document root 경로를 그대로 넘깁니다. 경로가 다르면 사이트를 Raw 설정으로 바꿔 `fastcgi_param SCRIPT_FILENAME`을 고칩니다.
- 파일은 nginx 컨테이너에도 보여야 합니다(정적 파일과 같음). 호스트 디렉터리라면 compose에서 nginx 서비스에 같은 경로로 마운트합니다. 소켓을 쓰면 소켓 디렉터리도 붙입니다.

### 저장하면 적용 대기가 됩니다

**저장**을 눌러도 nginx는 바로 바뀌지 않습니다. 메뉴의 **적용** 숫자가 늘어나고, [적용](07-apply.md) 화면에서 diff를 확인한 뒤 반영합니다. 적용하기 전에는 변경을 취소할 수 있습니다.

## 사이트 옵션

폼 아래의 접힌 묶음을 펼쳐 정합니다. 비워 두면 쓰지 않습니다.

### 경로별 라우팅 (location)

v1.5.0부터 리버스 프록시와 정적 파일 사이트는 경로마다 다른 곳으로 보낼 수 있습니다. 프런트엔드는 정적 파일로 두고 `/api/`만 백엔드로 넘기거나, 프록시 사이트에서 업로드 파일만 nginx가 바로 주게 할 때 씁니다. 줄마다 `경로 대상`을 적습니다.

```
/api/ http://127.0.0.1:8080/
/files/ /srv/uploads
```

- 대상이 `http://`·`https://` 주소면 그 경로를 프록시합니다(`proxy_pass`). 주소 끝에 경로를 적으면(위처럼 `/`만이라도) location 경로를 떼고 넘깁니다. `/api/users` 요청이 백엔드에는 `/users`로 갑니다. 호스트:포트까지만 적으면 `/api/users` 그대로 넘깁니다.
- 대상이 `/`로 시작하는 디렉터리면 그 디렉터리의 파일을 줍니다(`alias`). `/files/a.png`는 `/srv/uploads/a.png`가 됩니다. 디렉터리는 nginx 컨테이너 안에 있어야 합니다.
- 경로마다 `location ^~ 경로`가 생겨 정규식 location보다 먼저 골라집니다. 경로 `/` 하나만은 기본 location이라 쓸 수 없습니다.
- 아래 접근 제한, 속도 제한, 보안 헤더는 경로에도 똑같이 걸립니다. 프록시 경로는 사이트의 타임아웃·WebSocket 설정을 따릅니다.
- gRPC 프록시와 PHP 사이트에는 쓸 수 없습니다. PHP는 `^~` 경로가 `.php` 처리를 건너뛰어 PHP 소스가 그대로 나갈 수 있기 때문입니다.

### 점검 모드

v1.5.0부터 배포나 DB 작업 동안 사이트를 잠시 막고 안내 페이지를 보여 줄 수 있습니다. **점검 모드 켜기**를 체크하고 적용하면 방문자는 `503`과 **안내 문구**(비우면 한국어·영어 기본 문구)를 보고, 브라우저와 검색 엔진에는 `Retry-After: 600`(10분 뒤 다시)이 갑니다. 끄고 다시 적용하면 평소대로 돌아옵니다.

- **점검 중에도 들어올 수 있는 주소**에 작업자 IP나 CIDR을 적으면 그 주소에서는 평소처럼 사이트를 보고 확인할 수 있습니다.
- 경로별 라우팅의 경로와 PHP의 `.php` 요청까지 모두 막고, Let's Encrypt 인증서 발급 경로는 막지 않습니다.
- 안내 문구는 500자까지이고 따옴표(`'`), 역슬래시, `$`, 중괄호는 쓸 수 없습니다(nginx 설정 문자열을 깨뜨리기 때문입니다).
- 점검 중인 사이트는 사이트 목록과 사이트 화면에 **점검 중**으로 보입니다.

### 백엔드 장애 안내 페이지

리버스 프록시와 PHP 사이트에서 백엔드가 죽었거나 응답이 늦으면 방문자는 nginx 기본 `502 Bad Gateway`·`504 Gateway Time-out` 페이지를 봅니다. v1.7.0부터 **백엔드 장애 때 안내 페이지 보여 주기**를 켜면 그 대신 **안내 문구**(비우면 한국어·영어 기본 문구)를 보여 줍니다.

- nginx가 백엔드에 연결하지 못했거나 시간이 지나 낸 502·504만 바꿉니다. 백엔드가 직접 돌려준 오류 응답(API의 오류 JSON 등)은 그대로 갑니다.
- 응답 코드는 502 그대로라 모니터링·로드 밸런서는 장애를 알아챕니다. `Retry-After: 30`이 함께 갑니다.
- 문구 규칙은 점검 모드와 같습니다(500자, 따옴표·역슬래시·`$`·중괄호 불가). gRPC 프록시에는 쓰지 않습니다.

### 사용자 지정 헤더

v1.6.0부터 Raw 설정 없이 헤더를 더할 수 있습니다. 두 칸 모두 줄마다 `이름: 값`으로 적고, 20줄까지 씁니다.

- **응답 헤더**: 모든 응답에 붙습니다(`add_header … always`). CORS(`Access-Control-Allow-Origin: https://app.example.com`), `Content-Security-Policy: default-src 'self'; img-src *`, `X-Robots-Tag: noindex` 같은 헤더에 씁니다. 경로별 라우팅의 경로에도 똑같이 붙습니다. 모든 사이트 유형에서 씁니다.
- **백엔드로 보낼 헤더**(리버스 프록시): 백엔드 요청에 더합니다(`proxy_set_header`, gRPC는 `grpc_set_header`). `Host: api.internal`처럼 `Host`를 적으면 기본값(`$host`, 방문자가 친 도메인) 대신 그 값을 보냅니다. `X-Debug:`처럼 값을 비우면 그 헤더를 백엔드에 넘기지 않습니다.
- 값에 `$host`, `$remote_addr`, `$http_이름` 같은 nginx 변수를 쓸 수 있습니다. 없는 변수는 적용할 때 nginx 검사에서 걸립니다.
- 값에는 큰따옴표(`"`)와 역슬래시를 쓸 수 없고 500자까지입니다. `;`, `'`, 공백은 그대로 씁니다.
- `X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto`, `Upgrade`, `Connection`은 관리도구가 정하므로 백엔드 헤더로 적을 수 없습니다.

### 추가 도메인을 대표 도메인으로 보내기

`www.example.com`과 `example.com`처럼 이름이 둘이면 검색 엔진이 같은 내용을 두 주소로 보고, 쿠키·로그인도 주소마다 갈립니다. v1.6.0부터 **추가 도메인** 아래의 **추가 도메인을 대표 도메인으로 보내기**를 켜면 추가 도메인으로 온 요청은 대표 도메인으로 301 이동합니다. 리다이렉트 사이트를 따로 만들 필요가 없습니다.

- 경로와 쿼리는 그대로 붙습니다(`www.example.com/a?b=1` → `example.com/a?b=1`).
- HTTPS 인증서가 있으면 `https://대표 도메인`으로, 없으면 `http://대표 도메인`(80이 아닌 포트면 포트도)으로 보냅니다.
- 인증서는 지금처럼 대표·추가 도메인을 한 인증서로 받습니다. 추가 도메인도 Let's Encrypt 발급 경로는 그대로 받아 발급·갱신이 됩니다.
- 접근 제한·점검 모드 같은 사이트 옵션은 이동한 뒤 대표 도메인에서 걸립니다.

### 접근 제한 (IP, Basic 인증, 외부 인증)

사내 도구나 스테이징 사이트를 보호합니다. Let's Encrypt 인증 경로는 제한하지 않습니다.

| 항목 | 설명 |
| --- | --- |
| 허용할 주소 | IP나 CIDR을 줄마다 적습니다(예: `10.0.0.0/8`). 하나라도 적으면 목록에 없는 주소는 403으로 막습니다. |
| 차단할 주소 | 이 주소에서 오는 요청은 403으로 막습니다. 허용 목록보다 먼저 검사합니다. |
| Basic 인증 사용자 | 줄마다 `이름:비밀번호`로 적습니다(비밀번호 8자 이상). 이름만 적으면 저장된 비밀번호를 그대로 두고, 줄을 지우면 그 사용자를 지웁니다. 비밀번호는 해시로만 저장됩니다. |
| 허용 주소이거나 비밀번호가 맞으면 통과 | IP 제한과 비밀번호(또는 외부 인증)를 함께 쓸 때, 켜면 사내망은 인증 없이·밖에서는 인증으로 들어옵니다. 끄면 둘 다 맞아야 합니다. |
| 외부 인증 서버 (v1.4.0부터) | 요청마다 이 주소에 먼저 묻는 `auth_request`입니다. 2xx면 통과, 401·403이면 막습니다. oauth2-proxy(`http://oauth2-proxy:4180/oauth2/auth`), Authelia(`http://authelia:9091/api/authz/auth-request`), Authentik 같은 SSO를 사이트 앞에 둘 때 씁니다. 리버스 프록시 사이트에는 인증 서버가 준 사용자(`X-Auth-Request-User`, `X-Auth-Request-Email`)를 백엔드로 넘깁니다. |
| 로그인 주소 | 인증 서버가 401을 주면 이 주소로 보내고 원래 주소를 `rd` 파라미터로 붙입니다(예: `https://auth.example.com/oauth2/start`). 비우면 401을 그대로 돌려줍니다. |

외부 인증 서버는 nginx 컨테이너에서 닿는 주소여야 합니다. 같은 Docker 네트워크의 컨테이너 이름이나 호스트 IP를 적습니다. 인증 서버의 로그인 화면(예: `/oauth2/` 경로)을 같은 도메인에서 열어야 하는 SSO라면 그 경로를 따로 넘겨야 하므로 Raw 설정으로 바꿔 location을 더합니다.

### 요청 속도·동시 연결 제한

한 클라이언트가 너무 많은 요청을 보내지 못하게 합니다. 넘는 요청은 429로 거절합니다.

- **클라이언트 IP당 초당 요청 수**(예: 10)와 **버스트**(예: 20): 버스트만큼은 한꺼번에 와도 바로 처리하고, 그 뒤부터 초당 요청 수로 제한합니다. 페이지 하나가 요청을 여러 개 보내므로 넉넉히 잡습니다.
- **클라이언트 IP당 동시 연결 수**(예: 20)

### 성능·보안

| 항목 | 설명 |
| --- | --- |
| 응답 압축 (gzip) | HTML·CSS·JS·JSON 같은 텍스트 응답을 압축합니다. 정적 사이트는 미리 만든 `.gz` 파일이 있으면 그것을 보냅니다. |
| 보안 헤더 넣기 | `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy`를 붙입니다. 백엔드가 같은 헤더를 보내면 중복될 수 있습니다. |
| HSTS | 브라우저가 1년 동안 이 도메인을 HTTPS로만 엽니다. HTTPS 사이트에서만 쓸 수 있고, 켠 뒤에는 HTTPS를 끄기 어려우니 HTTPS가 안정적일 때 켭니다. |
| HTTP/3 (QUIC) | UDP 443으로 HTTP/3를 받습니다. HTTPS 사이트에서만 쓸 수 있고 nginx 컨테이너의 `443/udp`가 열려 있어야 합니다. |
| 최대 요청 크기 | 파일 업로드처럼 큰 요청을 받을 때 늘립니다(MB, 비우면 1, 0이면 제한 없음). 넘으면 413을 돌려줍니다. |
| 믿을 프록시 주소 / 실제 IP가 담긴 헤더 | 이 nginx 앞에 로드 밸런서나 CDN이 있으면 그 주소를 적습니다. 그 주소에서 온 요청은 헤더의 IP를 실제 클라이언트 IP로 보고 로그·IP 제한·속도 제한에 씁니다. |
| 프록시 캐시 유지 시간 | 리버스 프록시에서, 백엔드의 성공 응답(200, 301, 302)을 이 시간(분) 동안 저장해 바로 돌려줍니다. `Cache-Control: no-store`나 `Set-Cookie`가 있는 응답은 캐시하지 않습니다. 적중 여부는 `X-Cache-Status` 헤더로 봅니다. |
| 디렉터리 리스팅 | 정적 파일에서, `index.html`이 없는 폴더를 열면 파일 목록을 보여 줍니다. 공개해도 되는 폴더에서만 켭니다. |

폼에 없는 헤더(예: `add_header`로 붙이는 사용자 정의 헤더, CORS 헤더)나 location 여러 개가 필요하면 [Raw 설정](#raw-설정-사이트)으로 고칩니다.

## HTTPS

폼의 **HTTPS**에서 세 가지 중 하나를 고릅니다. 나중에 바꿀 수도 있습니다.

| 선택 | 언제 고르나 |
| --- | --- |
| 사용 안 함 (HTTP만) | 도메인을 아직 이 서버로 연결하지 않았거나 테스트용 사이트일 때 |
| Let's Encrypt 인증서 발급 | 무료 인증서를 자동으로 받고 만료 전에 갱신합니다. 대표·추가 도메인이 모두 이 서버를 가리키고 인터넷에서 80 포트로 들어올 수 있어야 합니다. 와일드카드 도메인은 받을 수 없습니다. |
| 업로드한 인증서 사용 | 와일드카드 인증서나 사내 CA 인증서처럼 [인증서 화면](09-certs.md#인증서-업로드)에 올린 인증서를 고릅니다. 자동으로 갱신되지 않습니다. |

<p align="center"><img src="images/site-form-https.png" alt="사이트 폼의 HTTPS 선택" width="860"></p>

**Let's Encrypt**를 고르면 이렇게 진행됩니다.

1. 저장하고 [적용](07-apply.md)합니다. 이때까지는 HTTP로만 응답합니다.
2. 사이트가 적용되면 관리도구가 인증서 발급을 시작합니다.
3. 발급되면 HTTPS 설정(`listen 443 ssl`, `http2`)이 자동으로 더해져 적용되고, 이력에 **인증서 발급** 버전이 남습니다.
4. **HTTP 요청을 HTTPS로 넘기기**를 켜면 `http://`로 들어온 요청을 `https://`로 301 이동시킵니다(인증 경로는 예외).

HTTPS 없이 만든 사이트도 나중에 사이트 화면의 **Let's Encrypt 인증서 발급**나 [인증서 화면](09-certs.md#lets-encrypt-인증서-발급)에서 HTTPS를 켤 수 있습니다. 발급에 실패하면 사유가 사이트 화면에 보이고, 잠시 뒤 자동으로 다시 시도합니다. 처음에는 [Let's Encrypt 설정](09-certs.md#lets-encrypt-설정)에서 스테이징으로 시험해 보길 권합니다.

## 사이트 화면

사이트 목록에서 도메인을 누르면 사이트 화면이 열립니다.

<p align="center"><img src="images/site-detail.png" alt="사이트 화면" width="860"></p>

- **제목 옆 버튼**: **로그 보기**([11장](11-logs.md)), **변경 이력**(이 사이트가 바뀐 버전만, [8장](08-versions.md#사이트별-이력)), **복제**([아래](#사이트-복제)), **활성화/비활성화**, **사이트 삭제**
- **설정**: 만들 때와 같은 폼으로 값을 고치고 **저장**을 누릅니다. 도메인은 바꿀 수 없습니다.
- **HTTPS 인증서**: 인증서 상태(발급됨, 발급 대기, 실패)와 만료일, 발급 버튼
- **설정 파일**: 지금 적용된 nginx 설정(파일 경로가 제목입니다). 아래 **Raw 편집**으로 Raw 편집기를 엽니다.
- 가져온 사이트라면 **소스 파일** 경로가 보이고, 소스 파일이 바뀌면 **소스에서 다시 가져오기**가 나타납니다([5장](05-import.md#소스-파일이-바뀌었을-때)).

### 사이트 복제

v1.6.0부터 비슷한 사이트를 하나 더 만들 때 사이트 화면의 **복제**를 누릅니다. 새 사이트 폼이 그 사이트의 유형·포트·대상·옵션으로 채워져 열리고, 도메인만 적고 **저장**하면 됩니다. 저장하기 전에는 아무것도 만들지 않습니다.

- 대표·추가 도메인은 다른 사이트와 겹칠 수 없어 비워 둡니다.
- 비밀번호 보호 사용자는 옮기지 않습니다(비밀번호는 해시로만 남아 옮길 수 없습니다). 필요하면 새로 적습니다.
- 업로드한 인증서는 도메인이 다를 수 있어 옮기지 않고, HTTPS였다면 Let's Encrypt로 바뀝니다.
- Raw 설정 사이트에는 복제 버튼이 없습니다.

### 사이트 담당자

사이트마다 담당 멤버를 한 명 정할 수 있습니다(v1.2.0부터). 멤버는 담당한 사이트만 보고 고치고 적용합니다.

<p align="center"><img src="images/site-owner.png" alt="사이트 화면의 담당자 선택" width="860"></p>

1. 관리자가 사이트 화면 위쪽의 **담당자**에서 멤버를 고릅니다. 비우려면 **담당자 없음**을 고릅니다.
2. **담당자 저장**을 누릅니다.

담당자를 바꿔도 설정 파일은 바뀌지 않으므로 적용할 것이 생기지 않습니다. 적용 대기 중인 변경이 있으면 그 변경도 새 담당자에게 넘어갑니다. 변경은 감사 로그에 **사이트 담당자 변경**으로 남습니다.

멤버에게는 다음처럼 담당 사이트만 보입니다. 다른 사이트 주소를 직접 열어도 "찾을 수 없음"이 나옵니다.

<p align="center"><img src="images/member-sites.png" alt="멤버가 보는 사이트 목록" width="860"></p>

### 활성화와 비활성화

**비활성화**는 사이트 설정을 nginx가 읽지 않게 하는 변경을 적용 대기에 올립니다. 적용하면 사이트가 응답하지 않고, 설정과 이력은 그대로 남아 **활성화**로 언제든 되살립니다. 잠시 멈출 때 씁니다.

꺼 둔 사이트의 Let's Encrypt 인증서는 자동으로 갱신하지 않습니다(nginx가 그 도메인에 응답하지 않아 갱신이 실패하기 때문입니다). 다시 켜서 적용하면 갱신할 때가 지난 인증서는 바로 새로 발급합니다.

### 사이트 지우기

더 쓰지 않는 사이트는 지웁니다(v1.3.0부터). 꺼 둔 사이트도 도메인을 잡고 있어 같은 도메인으로 새 사이트를 만들 수 없으니, 다시 쓸 일이 없으면 지우세요.

1. 사이트 화면 제목 옆의 **사이트 삭제**를 누르고, 확인 창에서 **확인**을 누릅니다.
2. 사이트 파일(과 비밀번호 보호 파일)을 삭제가 적용 대기에 올라가고 사이트에 **삭제 대기**가 붙습니다.
3. [적용 화면](07-apply.md)에서 diff를 확인하고 적용하면 nginx와 사이트 목록에서 빠집니다. 적용하기 전에 변경을 취소하면 그대로 남습니다.

- 적용하지 않은 편집이 있는 사이트는 지울 수 없습니다. 먼저 적용하거나 버립니다.
- 한 번도 적용하지 않은 새 사이트는 적용할 것 없이 바로 없어집니다.
- 지운 뒤에도 이력은 남습니다. 지우기 전 버전으로 롤백하면 사이트가 Raw 설정 사이트로 다시 생깁니다([8장](08-versions.md)).
- 사이트 로그 파일은 지우지 않습니다. 사이트가 쓰던 인증서는 갱신을 멈추고, 인증서 화면에서 지울 수 있습니다([9장](09-certs.md#쓰지-않는-인증서-지우기)).
- 멤버는 담당 사이트만 지웁니다. 감사 로그에 **사이트 삭제**로 남습니다.

## Raw 설정 사이트

폼에 없는 설정이 필요하면 사이트 화면의 **Raw 편집**을 누릅니다(관리자). Raw 설정은 `server_name`이나 `include`로 다른 사이트에 영향을 줄 수 있어, 멤버는 폼으로만 고칩니다. Raw 설정 사이트를 맡은 멤버는 내용과 로그를 보고 켜고 끌 수 있고, Raw 설정을 고칠 일은 관리자에게 요청합니다. nginx 문법 강조가 있는 편집기가 열리고, 저장하면 적용 대기가 됩니다.

- Raw 편집기에서 저장한 사이트는 **Raw 설정** 유형이 되어, 폼이 설정을 다시 덮어쓰지 않습니다. 이후에는 Raw 설정으로만 고칩니다.
- Raw 변경을 적용하기 전이라면 적용 화면에서 그 변경을 취소해 폼 사이트로 돌아갈 수 있습니다.
- Raw 설정 사이트의 HTTPS는 설정 파일에서 직접 켭니다. 인증서를 [업로드](09-certs.md#인증서-업로드)한 뒤 설정에 경로를 적습니다. Let's Encrypt 자동 발급은 폼 사이트에서만 됩니다.
