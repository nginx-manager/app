# 6. 스트림 (TCP/UDP)

데이터베이스, MQTT, SSH, DNS, 게임 서버처럼 HTTP가 아닌 서비스를 nginx 뒤에 둡니다. 받은 TCP/UDP 연결을 내용을 보지 않고 그대로 백엔드로 넘깁니다(nginx stream 모듈). 포트는 서버 전체가 함께 쓰므로 스트림은 관리자가 다룹니다.

## 스트림 만들기

**스트림** 메뉴에서 **스트림 추가**를 누릅니다.

<p align="center"><img src="images/stream-form.png" alt="스트림 추가 폼" width="860"></p>

| 항목 | 설명 |
| --- | --- |
| 프로토콜 | 연결을 유지하는 서비스(DB, MQTT, SSH, Redis)는 TCP, DNS·syslog·일부 게임 서버는 UDP |
| listen 포트 | nginx가 연결을 listen 포트. 프로토콜과 포트가 설정 파일 이름(`stream.d/tcp-5432.conf`)이 되며 저장한 뒤에는 바꿀 수 없습니다. 80, 443, 7070, 8081, 9000과 사이트가 쓰는 포트는 쓸 수 없습니다. |
| 백엔드 | `호스트:포트`를 줄마다 하나씩(예: `10.0.0.5:5432`, 최대 32개). 호스트 이름은 nginx가 설정을 읽을 때 찾을 수 있어야 합니다. |
| 로드 밸런싱 방식 | 백엔드가 여럿일 때. 차례대로(기본), 연결이 가장 적은 백엔드로, 같은 클라이언트 IP는 같은 백엔드로 |
| 연결 타임아웃 | 백엔드와 연결을 맺을 때까지 기다리는 시간(초, 비우면 60). 넘으면 다음 백엔드를 시도합니다. |
| 유휴 타임아웃 | 양쪽 모두 이 시간 동안 아무것도 보내지 않으면 연결을 끊습니다(초, 비우면 600). 오래 유지되는 DB·MQTT 연결은 길게 잡습니다. |
| 허용할 주소 | 이 IP·CIDR에서 오는 연결만 받습니다(v1.7.0). 비우면 모두 받습니다. DB·SSH 포트는 사내 대역만 적어 두길 권합니다. |
| 막을 주소 | 이 IP·CIDR에서 오는 연결을 끊습니다. 허용할 주소보다 먼저 걸립니다. |
| PROXY protocol | TCP 스트림에서 켜면 연결 앞에 PROXY protocol 헤더를 붙여 백엔드가 실제 클라이언트 IP를 압니다(`proxy_protocol on`). 백엔드가 PROXY protocol을 받도록 설정돼 있어야 하고, 아니면 연결이 깨집니다. |
| 메모 | 무엇을 위한 스트림인지 적어 둡니다. 설정 파일 맨 위 주석으로도 들어갑니다. |

사이트와 같이 저장하면 적용 대기가 되고, [적용](07-apply.md) 화면에서 적용합니다.

## 포트 열기

nginx 컨테이너는 compose 파일에 적은 포트만 밖으로 엽니다. 스트림을 만든 뒤 compose 파일의 `nginx` 서비스 `ports`에 그 포트를 더하고 nginx를 다시 띄웁니다. 스트림 화면에도 더할 줄이 안내됩니다.

```yaml
  nginx:
    ports:
      - "80:80"
      - "443:443"
      - "443:443/udp"
      - "5432:5432"      # TCP 스트림
      - "53:53/udp"      # UDP 스트림
```

```bash
docker compose up -d nginx
```

## 고치기와 지우기

스트림 목록에서 포트를 눌러 스트림 화면을 엽니다. 백엔드, 로드 밸런싱 방식, 타임아웃, 접근 제한, PROXY protocol, 메모를 고칠 수 있습니다. 접근 제한을 건 스트림은 목록에 **접근 제한**으로 보입니다. 프로토콜과 포트는 바꿀 수 없으니, 바꾸려면 **스트림 삭제**로 지우고 새로 만듭니다.

SNI로 연결을 나누는 것처럼 폼에 없는 설정은 [설정 파일](10-files.md)에서 `stream.d/` 아래 파일을 Raw 설정으로 고치거나 새로 만듭니다. Raw 설정으로 고친 스트림은 **Raw 편집** 표시가 붙고 폼이 다시 덮어쓰지 않습니다.
